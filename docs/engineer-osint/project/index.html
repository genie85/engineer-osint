Co projekt dělá

ENGINEER OSINT odděluje výzkumnou vrstvu, kanonická data, prezentační transformace a veřejné UI. Cílem je dohledatelná práce se zdroji, časem a změnami bez tichého přepisování historie.

Collection

Sběr a normalizace

Průběžné získávání otevřených zdrojů, jejich třídění, deduplikace a převod do jednotného datového rámce.

Evidence

Důkazní vazby

Oddělení tvrzení, zdrojů, entit a časových pozorování tak, aby bylo možné zpětně dohledat, z čeho závěr vznikl.

Temporal

Historický kontext

Model kombinuje aktuální změny, historické doplnění a obohacování entit; starší informace nemají být prezentovány jako aktuální bez nového potvrzení.

Integrity

Append-only historie

Nové běhy se přidávají jako neměnné záznamy. Opravy a odvolání mají být verzované a dohledatelné, nikoli provedené tichou změnou.

Presentation

Veřejný dashboard

Renderer smí data filtrovat, řadit, lokalizovat a vizualizovat, ale nemá vytvářet nové faktické hodnoty mimo perzistentní datovou vrstvu.

QA

Vícevrstvé kontroly

Samostatně se sleduje výzkumný běh, build, statické kontroly, browser regresní testy, deploy a veřejný read-back.

Kontrolní principy

  • Zdrojová atribuce a časová disciplína.
  • Oddělení faktů, odvozenin a prezentačních transformací.
  • Kontrola konzistence kanonického snapshotu a navazujících runů.
  • Samostatné sledování lokalizace CZ/EN a veřejného UI.
  • Explicitní evidence známého migračního a legacy dluhu.
Poznámka k interpretaci: tato stránka je prezentační rozcestník. Aktuální fakta, entity, časové osy a zdroje je nutné číst v živém dashboardu a v kanonických datech projektu.
